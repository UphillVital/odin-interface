# COMPONENT RULES v1

## Buttons
- clear purpose
- one primary action per work zone
- destructive actions require confirmation
- system actions must show state/result

## Panels
- structured
- readable
- no overload
- each panel must answer: what is this, why is it here, what can I do?

## Navigation Tree
- reflects the system map
- not decorative
- must help the user understand hierarchy

## Work Zones
- activated by intent, mode, command or state
- show context, available actions and next step

## Status
- always visible
- meaningful
- not fake

## Rule
Every component must have a function.
