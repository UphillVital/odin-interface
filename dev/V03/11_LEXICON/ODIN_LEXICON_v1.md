# ODIN LEXICON v1

Purpose: Shared dictionary for ODIN communication, commands, modes, states, and system concepts.

---

## 1. Why This Exists

ODIN must support understanding “from half a word.”

That requires a structured shared vocabulary.

---

## 2. Level 1 — Core Terms

| Term | Meaning |
|---|---|
| ODIN | Core system: engine + control + logic |
| DT | Deutsch Trainer product built on ODIN |
| OIS | ODIN Interaction System |
| Intent | What the user/system is trying to do |
| Mode | Behavioral state of the system |
| State | Current factual system condition |
| Work Zone | Intent-driven working area |

---

## 3. Level 2 — Execution Terms

| Term | Meaning |
|---|---|
| BUILD | Create or assemble something |
| FIX | Correct a detected issue |
| QA | Quality check |
| EXPORT | Prepare output/package |
| PACKAGE | Controlled bundle for transfer or deployment |
| LOCK | Fixed rule or decision that must not be broken |

---

## 4. Level 3 — Interface Terms

| Term | Meaning |
|---|---|
| System Map | Live navigation model showing system relationships |
| File Workspace | Controlled editor/diff/approval/package environment |
| Assisted Mode | Guidance layer for orientation and next steps |
| Master Start | Primary launch/generation workflow for ODIN products |

## 5. Level 4 — Quality Terms

| Term | Meaning |
|---|---|
| СЯ | Quality/self-support system with automatic rules |

| No Fake Logic | No simulation pretending to work |

## 6. Lexicon Rule

If a term becomes important in workflow, it must be added here.
