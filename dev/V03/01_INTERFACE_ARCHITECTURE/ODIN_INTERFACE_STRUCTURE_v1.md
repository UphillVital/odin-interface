# ODIN INTERFACE STRUCTURE v1

## Concept

ODIN Interface = Мій Кабінет управління в ОДІН.

It must be:
- understandable
- hierarchical
- flexible
- visual
- safe
- system-driven
- suitable for large work without losing context

## Main Layout

```text
┌─────────────────────────────────────────────┐
│ Top Bar: ODIN status / mode / version       │
├───────────────┬─────────────────────────────┤
│ Left Tree     │ Main Workspace              │
│ Navigation    │ Active screen/window        │
│               │                             │
│ Manual/Help   │ Right details / state panel │
└───────────────┴─────────────────────────────┘
```

## Mandatory Screens

1. Command Center
2. System Map
3. OIS / Interaction System
4. Products
5. Modules
6. File Workspace
7. Decisions / Locks
8. Experiments
9. QA / Validation
10. Manual / Help

## User Guidance

When relationships are unclear, the interface should help the user understand:
- what this screen controls
- what is connected to it
- what can be safely changed
- what is locked
- what the next recommended action is
